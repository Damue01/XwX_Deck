# 快速开始

本文对应公开版 `1.1.1`。
已发布包的功能以对应版本标签为准。
安装步骤见 [下载与安装](download.md)。

## 首次设置

新安装没有预置 API 服务。
全屏引导先检测本机客户端。
缺少推荐客户端时，提供官方下载入口。
后续可检测并选择已有配置。
也可跳过引导，再从设置中导入。

导入须由用户明确选择。
支持 API 配置及可识别的本机授权账号。
来源文件保持只读。
重复项目跳过，来源变化时要求重新检测。
导入不会自动切换客户端。
详见 [用户手册](user-manual.md)。

## 添加服务

1. 打开设置中的“添加配置”。
2. 选择 API 服务或自定义配置。
3. 填写名称、URL 和 Key，再保存。
4. 打开模型页，明确选择服务与模型。
5. 新建客户端对话，核对实际响应与上游。

服务预设只预填表单。
保存前不会创建连接。
保存不会自动发送模型测试请求。
目录存在、配置保存和请求成功分别验证。
目录离线时，已保存的选择继续保留。

第三方连接用于客户端的模型请求。
不会替换 ChatGPT 网页普通聊天的模型。
协议和地址按配置及服务声明处理。
不能仅凭厂商或模型名称推断协议。

## 查看请求

开启 Trace 后，先新建测试对话。
确认请求确实进入本机 Gateway。
仪表盘显示会话、用量、请求与最终上游。
已知金额正常显示。
无法计价的请求单独提示数量与原因。
参考费用仍需与服务账单分别核对。

切换服务后，续接同一测试会话。
核对上下文、实际路由与会话归属。
不能以另开会话成功代替续接验证。

停止 Trace 会恢复受管字段并关闭 Gateway。
用户选择的服务与模型继续保存。
需要协议转换时，须重新开启 Trace。
活动请求、工具等待和配置冲突分别处理。
退出不会自动关闭或重启客户端。

Trace 可能包含完整请求与响应。
认证请求头会脱敏，业务正文仍需人工检查。
测试与真实环境要求见 [测试策略](testing-strategy.md)。

公开版不提供配置同步、工具页或对话诊断。
