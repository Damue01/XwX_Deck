# XwX Deck 用户手册

> 最后核对日期：2026-10-08
> 适用版本：XwX Deck 1.0.0

## 页面

- **Trace**：开始或停止追踪，查看累计 Token、费用、吞吐和客户端接入状态。
- **模型**：管理 Claude / ChatGPT 使用的模型服务与模型选择。
- **工具**：只读检查 ChatGPT 的 SQLite 对话索引、Session 文件和 Provider 元数据是否一致。
- **仪表盘**：在本地浏览器中查看请求详情、会话和筛选结果。
- **设置**：管理服务连接、主题、Trace 外观、数据目录、日志目录、开机启动与版本信息。

独立版不提供客户端配置同步或 Excel 转 Markdown。工具页当前只包含本地对话诊断，不修改或迁移会话文件。

设置页底部的“诊断与修复”沿用 上游 的当前交互：显示当前问题、最近一次失败与对应处理操作，并允许移除最近一次失败；保留“重置 XwX Deck”入口，不再显示旧的快速修复与清理缓存块。重置会清理设置、缓存、Trace 和日志；Claude / ChatGPT 核心配置默认保留，只有额外确认时才处理。

手动 **Trace 索引检查与修复** 在设置的 Trace 分组中。先停止 Gateway，再检查损坏或丢失的索引；确认后备份原索引与修复清单，从原始 Trace 记录重建，不修改原始 JSONL。

## 服务切换

新安装没有预置 API 连接。已有单连接会迁移到本地 Provider registry；每个连接分别保存 ChatGPT 模型、窗口与 Claude 模型映射。两种客户端可选择不同连接。连接失败后仍可在设置中编辑；没有模型目录时可填写模型 ID。

官方订阅开启 Trace 时，仅将模型地址 `openai_base_url` 指向本地 Gateway，账户与工作区地址 `chatgpt_base_url` 保持官方 HTTPS。保留官方登录不会绕过客户端的工作区地址校验。

官方目录来自 Codex home 的模型缓存。外部配置变化会保留并提示；明确切换服务后才更新受管字段和目录指针，外部目录文件不会删除。切换连接时不会把旧模型目录当作新服务返回的目录。

模型目录先使用同一连接的缓存，再后台刷新。离线或目录超时不会撤销已保存的服务和模型选择；前台目录等待最多占用总计 2 秒。新连接名称使用英文字母、数字、下划线或连字符，旧名称保持不变。Claude Desktop 接入是默认关闭的模型连接选项，不包含规则、技能或文件同步。

客户端与官方模型服务图标分别可折叠，默认收起。折叠仅隐藏快捷入口，不隐藏自定义、已保存连接和编辑草稿。展开后的模型服务入口横向展示七个官方预设，可通过触控板横向滑动、悬停时普通鼠标滚轮或 Tab 键聚焦浏览，不显示滚动条或左右箭头，点击后查看配置卡片。右上角固定的“自定义”按钮直接打开连接表单，自定义与各官方预设分别保留未保存草稿。

官方服务与各个兼容连接使用独立的续接状态。Gateway 会把其他连接记住的旧模型名转成当前连接所选模型，目标目录已有的有效模型和手填的未知模型名保持原样；HTTP、WebSocket 与压缩请求沿用相同规则。正在运行的客户端可能缓存旧连接；切换后当前任务未生效时，重新打开客户端即可。XwX Deck 不会为了切换服务自动关闭或启动 ChatGPT。

## Trace 数据

Trace 新配置默认上限为 1 GB，并开启「超出上限自动清理」，从最旧的完整对话开始清理，保留正在记录的对话。已有用户保存的容量及自动清理选择保留。在设置的 Trace 分组中可调整上限或关闭自动清理，关闭后上限仅用于提醒。将上限设为 0 GB 会切换为仅用量模式，确认后清理详细 Trace，保留用量统计。手动删除采用可回滚事务；索引损坏时停止写入和删除，先检查并手工修复。

Trace 保存在本地数据目录，可能包含完整提示词、上下文、工具参数、工具结果和模型响应。认证请求头会脱敏，但正文中的业务数据不会自动删除。共享日志前应人工检查。

用量按客户端请求的模型名归档；上游返回不同内部模型名时会保留为实际服务模型，用于价格回退和提示。分档价格、峰谷时段、短回复折扣及缓存 TTL 只有在 Trace 保存了对应分桶时才参与估算；数据不足时显示不可用或部分合计，不会把未知费用显示为零。

模型能力除了随包注册表和外部目录，还可以采用“当前 Gateway 实测”结果。实测层只覆盖真正观察到的字段，例如模型是否实际产生 reasoning token；不会用一次请求猜测上下文长度或价格。未实测的新模型继续按保守能力处理。

## 退出

- 关闭窗口：隐藏管理器；必要时 Gateway 继续服务客户端。
- 托盘、菜单栏、Dock 和 Cmd+Q 的退出：先恢复受管配置，再停止 Gateway。
- 连接恢复为所选 Provider 的远端配置与专属凭据；不会自动切换官方。需要协议转换的模型仍依赖本地 Gateway，界面会提示开启 Trace。
- 恢复仅处理 XwX Deck 实际写过且未被外部修改的字段；冲突保留并提示，写入失败回滚。配置仍依赖本地端口时取消退出，保留 Gateway 与恢复记录。
- 有正在生成的回复或工具续接时：先显示确认，避免静默中断。

## 排障顺序

1. 检查客户端是否启用以及 Trace 是否开始。
2. 检查服务地址、密钥和模型是否有效。
3. 查看运行日志与 Trace 最终上游地址。
4. 若服务刚切换且当前任务仍走旧连接，重新打开客户端后再试。

## 只读对话诊断

主表只显示“对话、检查结果、更新时间”三列，每页最多 120 条；文件、路径和字段信息在展开详情后显示。扫描在后台 worker 中进行，支持缓存、分页和取消。只查询 SQLite 元数据及 JSONL 第一条 `session_meta`，不读取后续对话正文。离开页面取消未完成的扫描，后台缓存闲置 3 分钟后释放；详情按需加载。路径打开只允许 Codex home 内真实存在的路径，并检查符号链接目标，阻止越界。

## 更新

启动后会检查新版，也可以在设置中点击版本号检查。Windows 下载后可重启更新；保持运行时，会在 02:00–05:00、系统空闲至少 15 分钟且没有需确认的活动会话时自动安装。取消某个版本后，重启也不会自动安装它，主动重新下载可恢复。

macOS 下载后校验 DMG。点击“打开安装包”会进入安全退出流程；等旧应用退出，再拖入“应用程序”并选择替换，从“应用程序”打开新版。不要从安装映像直接运行；安装完成并核对一致后会尝试推出映像。没有运行新版、映像仍被其他程序占用等情况下，需在 Finder 手动推出。

检查失败不代表已是最新。发布内容变化时请重新检查。Windows 已替换文件但自动启动失败时，新版和 `.previous` 备份均保留，按提示手动打开原路径程序。
