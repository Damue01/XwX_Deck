# 测试执行方式

要求与结果分开维护。
[功能清单](core-functional-acceptance-checklist.md) 定义核心测试点。
`test-catalog.json` 维护编号与脚本映射。

| 层级 | 验证范围 | 证据 |
| --- | --- | --- |
| P | 程序、合成服务与浏览器交互。 | 源码指纹、命令结果和断言。 |
| R | 真实 CLI、正式上游与实际授权。 | 精确模型、服务、请求与返回。 |
| U | 隔离候选的原生界面操作。 | 窗口、实际回读和对应请求。 |
| H | 实际安装、系统对话框和物理操作。 | 系统、包哈希及人工操作记录。 |

真实 CLI 可由程序驱动。
合成上游仍属于 P 层。
RPC 成功不代表界面或真实链路通过。

先编译当前源码，再运行对应测试。
失败时保留首次结果和复测结果。
修改后重跑受影响的检查。
最终结果必须绑定同一源码指纹。
不同平台的结果分别登记。

开启 Trace 后使用新建的测试对话。
切换服务后续接同一对话。
核对上下文、实际路由和会话归属。
停止后核对配置恢复与直连。
不能用另开对话成功代替续接验收。

默认检查为 `npm run check:quality`。
界面另跑仪表盘、分页、Toast 和原生窗口。
公开边界与文档检查在提交前执行。
测试不改正常客户端、凭据或历史记录。
