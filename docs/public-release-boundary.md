## 仓库隐私检查

内部名称限制用于保护维护者的工作信息。
检查对象包括源码、文档与构建产物。
Git 检查覆盖本地全部引用可达的对象。
其中包括历史文件内容、文件名与提交信息。
完整历史缺失时，检查会失败。
远端独有引用与不可达对象需要另行审计。

原生编译将维护者目录映射为公共路径。
编译完成后，检查二进制中的内部名称与本机路径。
检查覆盖 UTF-8 和 UTF-16 文本。
检查通过后才进行签名与公证。
macOS 最终验证再次检查主程序与更新辅助程序。

这些规则仅用于开发与发布检查。
应用不将内部名称作为用户输入的屏蔽词。
应用不因内部名称过滤或改写用户内容。
名称长度、控制字符与协议格式仍按现有规则校验。

正式公开发布仍需确认许可证、品牌授权与隐私说明。
签名、公证和安全报告渠道也需单独确认。

技术移植按能力域提交，范围与验证见 [技术吸收记录](upstream-port.md)。新安装 Provider registry 为空，不按内部名称预置连接；用户手工配置的名称原样保留。

## 发布前的配置验收

在隔离目录分别验收全新安装、已有 Deck 配置和外部客户端配置。检查 API 与 Coding Plan 的地址、协议、密钥及模型保存，使用本地上游实际请求验证切换、转换与续接。覆盖 Magpie / CC Switch / Claude CLI / Codex CLI 导入、重复项目、同名冲突、预览后源文件变化、目标配置外部变化与写入失败；确认来源文件和已有服务选择保留、订阅令牌不迁移、导入不激活连接。新手引导的检测只读，选择后才导入；已有用户无需重复导入。

配置检查不自动开启 Gateway、重启客户端或发送收费请求。正式服务商的套餐权限、真实额度与授权仍需在发布验收中单独确认，不能以本地回归通过替代。
